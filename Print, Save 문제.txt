반영한 내용 정리

1. PRINT 임시파일 번호 문제 → 번호를 순차로 찾던 방식을 버리고 매번 고유한 이름(OS 임시폴더 + UUID)을 
쓰도록 바꿔서, 뷰어가 이전 파일을 붙잡고 있어도 절대 안 겹치고 번호가 튀지도 않습니다.

2. 단일 PLOT의 PRINT/SAVE 크기 문제 → 지금까지 Multi Print/Save와 완전히 다른 옛날 코드를 쓰고 있었던 게 
원인이었습니다. 이제 일반 PRINT/SAVE도 Multi Print/Save의 "1개 선택" 케이스와 똑같은 코드를 타도록 
통일했습니다 ? 축 박스(Frame Size) 고정 + A4 중앙 배치 + 1.75배 확대가 이제 어디서 인쇄/저장하든 
동일하게 적용됩니다. (PNG/JPG일 때만 픽셀로 환산하던 부분도 이제 안 맞아서 제거했습니다 
? 이제 모든 포맷이 inch 기준으로 통일됩니다.)

3. 확대/여백 조정

단일(1/p): 1.75배 확대 (요청하신 대로)
4/p, 6/p: 20% 확대 (MULTI_PLOT_ENLARGE)
Title이 빈 경우 상단 여백을 0.6in → 0.15in로 대폭 축소 (보통 Title 없이 쓰신다고 하셔서)
칸 사이 간격도 0.25in → 0.15in로 축소

4. Multi Print/Save에 Comment/Arrow가 아예 안 들어가던 버그 → execute_plot_pipeline이 만든 
plotdef에 annotations/arrows를 저장하지 않고 있었고, create_multiplot_script도 그걸 넘겨받는
 부분이 없었습니다. 둘 다 고쳐서 이제 Multi Print/Save에도 Comment/Arrow가 반영됩니다.

확인이 더 필요한 것 ? 90도 회전 문제

이건 원인을 확정 짓지 못했습니다. Print와 Save가 (수정 전 기준으로) 같은 
execute_multi_plot_pipeline/create_multiplot_script를 타고 있어서 
코드상으로는 차이가 없어야 하는데, 왜 Print 결과만 회전되어 보였는지는 실제 파일을 봐야 확실합니다. 
이번 수정 이후에도 같은 증상이 재현되면, 그 PDF를 열어서 "문서 속성 
→ 페이지 크기(가로 x 세로)"를 확인해주시고, 가능하면 open_multi_plot_dialog의 Print 분기에서 
keep_script를 잠깐 True로 바꿔서 그 시점 .plt 스크립트도 같이 보여주시면 바로 짚어드리겠습니다.

참고: "sample_mul_1.pdf라고 물어봤는데 sample_mul_2pA.pdf로 저장됨" 같은 부분은 버그가 아니라, 
저장 대화상자에서 직접 이름을 바꿔서 저장하신 것으로 보입니다 
(asksaveasfilename은 제안 이름만 보여줄 뿐, 사용자가 그 자리에서 자유롭게 바꿀 수 있습니다)
 ? 신경 안 쓰셔도 됩니다.
