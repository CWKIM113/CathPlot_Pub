확인된 버그 1: 멀티플롯에서 Frame Size(W/H) 입력이 완전히 무시됨
execute_multi_plot_pipeline은 사용자가 입력한 Frame Size를 계산은 해두고(final_frame_width 등), 그걸 cache된 plotdef 객체에 직접 대입만 합니다. 그런데 create_multiplot_script의 페이지 크기는 그 값을 전혀 안 읽고 항상 _A4_SIZES[orientation](고정 A4)만 씁니다. 그래서 Frame Size를 뭘 넣든 멀티플롯에선 반영이 안 됩니다.
게다가 이 mutation 방식 자체도 위험합니다 ? 캐시에 저장된 plotdef 객체를 직접 고쳐버려서, 나중에 그 plot을 다시 쓰거나 다른 조합으로 멀티플롯을 만들 때 이전 설정이 계속 남아있게 됩니다.

확인된 버그 2: 선택한 plot 개수가 레이아웃 칸 수보다 많으면 겹침 발생 가능성 ? 유력한 원인
2/p는 2칸, 4/p는 4칸, 6/p는 6칸입니다. 그런데 몇 개를 선택했는지에 대한 검증이 전혀 없어서, 예를 들어 2/p를 선택한 채로 plot을 3개 이상 고르면, gnuplot이 정해진 칸(2칸) 안에 억지로 3번째 plot을 이어서 그리려다 겹치거나 페이지 밖으로 밀려나는 현상이 생길 수 있습니다. "겹치고 위아래로 안 나뉜다"는 증상과 정확히 일치합니다.
수정: 실행 전에 선택 개수와 칸 수를 비교해서, 넘으면 명확히 안내하고 막습니다.

def execute_print_dialog(self):
    idx = 1
    while True:
        temp_pdf = os.path.join(self.plot_dir, f"Print_Job_Temp_{idx}.pdf")
        if not os.path.exists(temp_pdf):
            break
        idx += 1

    try:
        success_path = self.execute_plot_pipeline("Batch", custom_filepath=temp_pdf, custom_format="PDF")
    except Exception as e:
        messagebox.showerror("Print Error", f"PDF 생성 중 오류가 발생했습니다:\n{e}")
        return

    if success_path and os.path.exists(success_path):
        threading.Thread(
            target=self._print_and_cleanup, args=(success_path,), daemon=True
        ).start()
